# 快速入门

你可以通过以下方式在应用中使用 Loro：

- [`loro-crdt`](https://www.npmjs.com/package/loro-crdt) NPM 包
- [`loro`](https://crates.io/crates/loro) Rust crate
- [`loro-swift`](https://github.com/loro-dev/loro-swift) Swift 包
- [`loro-py`](https://github.com/loro-dev/loro-py) Python 包
- [`loro-cs`](https://github.com/sensslen/loro-cs) 社区维护的 C# 包
- 也可以在 [Loro 的 Deno 示例仓库](https://github.com/loro-dev/loro-examples-deno)中找到示例列表

可以借助 [Loro Inspector](/docs/advanced/inspector) 调试并可视化 Loro 文档的状态与历史。

下文示例统一使用 `loro-crdt` JavaScript 包。

[![Open in StackBlitz](https://developer.stackblitz.com/img/open_in_stackblitz.svg)](https://stackblitz.com/edit/loro-basic-test?file=test%2Floro-sync.test.ts)

## 安装

```bash
npm install loro-crdt

# 或者
pnpm install loro-crdt

# 或者
yarn add loro-crdt
```

如果你使用的是 `Vite`，请在 vite.config.ts 中加入：

```ts no-run
import wasm from "vite-plugin-wasm";
import topLevelAwait from "vite-plugin-top-level-await";

export default defineConfig({
  plugins: [...otherConfigures, wasm(), topLevelAwait()],
});
```

<details>
<summary>⚠️ Vite 中的 DOMContentLoaded 定时问题</summary>

在 Vite 中使用 Loro 时，需要注意模块加载与 DOM 事件的时序问题。

**问题：** 下面的代码会导致页面没有任何渲染结果：

```ts no_run
import { LoroDoc } from "loro-crdt";

document.addEventListener("DOMContentLoaded", () => {
  const doc = new LoroDoc();
  // 在此编写逻辑…
});
```

**原因：** Vite 以异步方式加载 ES 模块，`loro-crdt` 内部的 WASM 初始化同样是异步的。当你在顶层导入模块却把逻辑放在 `DOMContentLoaded` 事件里执行时，事件触发时 WASM 可能尚未完成初始化，从而导致页面静默失败。

**解决方案：**

1. **移除事件监听器**（大多数场景推荐）：

   ```ts no_run twoslash
   import { LoroDoc } from "loro-crdt";

   const doc = new LoroDoc();
   // 在此编写逻辑…
   ```

2. **在事件监听器内使用动态导入**：

   ```ts no_run twoslash
   document.addEventListener("DOMContentLoaded", async () => {
     const { LoroDoc } = await import("loro-crdt");
     const doc = new LoroDoc();
     // 在此编写逻辑…
   });
   ```

动态导入可以确保模块及其 WASM 依赖加载完成后再执行代码。

</details>

如果你使用 `Next.js`，请在 next.config.js 中加入：

```js no-run
module.exports = {
  webpack: function (config) {
    config.experiments = {
      layers: true,
      asyncWebAssembly: true,
    };
    return config;
  },
};
```

## 简介

构建数据同步或实时协作应用众所周知是一项挑战，尤其当设备可能离线，或处于点对点网络时。Loro 可以帮你轻松应对这些问题。

当你用 Loro 来建模应用状态后，同步就会变得简单：

```ts twoslash
import { LoroDoc } from "loro-crdt";
const docA = new LoroDoc();
const docB = new LoroDoc();

// …在 docA 与 docB 上进行操作

// 假设 docA 与 docB 位于不同设备
const bytesA = docA.export({ mode: "update" });
// 以任意方式把字节发送给 docB
docB.import(bytesA);
// docB 现在拥有 docA 的全部变更

const bytesB = docB.export({ mode: "update" });
// 以任意方式把字节发送给 docA
docA.import(bytesB);
// docA 与 docB 现在同步，状态一致
```

保存应用状态同样简单：

```ts twoslash
import { LoroDoc } from "loro-crdt";
// ---cut---
const doc = new LoroDoc();
doc.getText("text").insert(0, "Hello world!");
const bytes = doc.export({ mode: "snapshot" });
// 这些字节可以写入本地存储、数据库或通过网络发送
```

加载应用状态：

```ts no_run twoslash
import { LoroDoc } from "loro-crdt";
const bytes = new Uint8Array();
// ---cut---
const newDoc = new LoroDoc();
newDoc.import(bytes);
```

Loro 还支持时光旅行，让你为应用加入版本控制。[进一步了解时光旅行功能](/docs/tutorial/time_travel)。

```ts no_run twoslash
import { LoroDoc } from "loro-crdt";
const doc = new LoroDoc();
const version = doc.frontiers();
// ---cut---
doc.checkout(version); // 将文档检出到指定版本
```

Loro 与 JSON schema 兼容。如果你的应用状态可以用 JSON 建模，大概率也能用 Loro 同步。由于需要遵循 JSON schema，Map 的键不得使用数字，也应避免循环引用。

```ts no_run twoslash
import { LoroDoc } from "loro-crdt";
const doc = new LoroDoc();
// ---cut---
doc.toJSON(); // 获取文档的 JSON 表示
```

## 入口：LoroDoc

LoroDoc 是使用 Loro 的入口。要使用 Map、List、Text 等类型并进行数据同步，你必须先创建一个 Doc。

```ts twoslash
import { LoroDoc, LoroText } from "loro-crdt";
// ---cut---
const doc = new LoroDoc();
const text: LoroText = doc.getText("text");
text.insert(0, "Hello world!");
console.log(doc.toJSON()); // { "text": "Hello world!" }
```

## 容器

`List`、`Map`、`Tree`、`MovableList`、`Text` 等 CRDT 类型统称为 `Container`。

以下示例展示了它们的基本操作：

```ts twoslash
import { LoroDoc, LoroList, LoroMap, LoroText } from "loro-crdt";
import { expect } from "expect";
// ---cut---
const doc = new LoroDoc();
const list: LoroList = doc.getList("list");
list.insert(0, "A");
list.insert(1, "B");
list.insert(2, "C");

const map: LoroMap = doc.getMap("map");
// map 只能使用字符串键
map.set("key", "value");
expect(doc.toJSON()).toStrictEqual({
  list: ["A", "B", "C"],
  map: { key: "value" },
});

// 删除索引 0 处的两个元素
list.delete(0, 2);
expect(doc.toJSON()).toStrictEqual({
  list: ["C"],
  map: { key: "value" },
});

// 在列表中插入一个文本容器
const text = list.insertContainer(0, new LoroText());
text.insert(0, "Hello");
text.insert(0, "Hi! ");

expect(doc.toJSON()).toStrictEqual({
  list: ["Hi! Hello", "C"],
  map: { key: "value" },
});

// 在 map 中插入一个列表容器
const list2 = map.setContainer("test", new LoroList());
list2.insert(0, 1);
expect(doc.toJSON()).toStrictEqual({
  list: ["Hi! Hello", "C"],
  map: { key: "value", test: [1] },
});
```

## 保存与加载

Loro 是纯粹的库，不处理网络协议或存储机制。你需要自行保存和传输 Loro 导出的二进制数据。

要保存文档，可以使用 `doc.export({ mode: "snapshot" })` 获取二进制表示；稍后通过 `doc.import(data)` 重新加载。

```ts twoslash
import { LoroDoc, LoroList, LoroMap, LoroText } from "loro-crdt";
import { expect } from "expect";
// ---cut---
const doc = new LoroDoc();
doc.getText("text").insert(0, "Hello world!");
const data = doc.export({ mode: "snapshot" });

const newDoc = new LoroDoc();
newDoc.import(data);
expect(newDoc.toJSON()).toStrictEqual({
  text: "Hello world!",
});
```

每次按键都导出完整文档效率不高。更好的做法是使用
`doc.export({ mode: "update", from: VersionVector })` 获取自上次导出以来的增量操作。

```ts twoslash
import { LoroDoc, LoroList, LoroMap, LoroText } from "loro-crdt";
import { expect } from "expect";
// ---cut---
const doc = new LoroDoc();
doc.getText("text").insert(0, "Hello world!");
const data = doc.export({ mode: "snapshot" });
let lastSavedVersion = doc.version();
doc.getText("text").insert(0, "✨");
const update0 = doc.export({ mode: "update", from: lastSavedVersion });
lastSavedVersion = doc.version();
doc.getText("text").insert(0, "😶‍🌫️");
const update1 = doc.export({ mode: "update", from: lastSavedVersion });

{
  /**
   * 可以先导入快照，再导入增量，以恢复文档最新状态。
   */

  // 导入快照
  const newDoc = new LoroDoc();
  newDoc.import(data);
  expect(newDoc.toJSON()).toStrictEqual({
    text: "Hello world!",
  });

  // 导入 update0
  newDoc.import(update0);
  expect(newDoc.toJSON()).toStrictEqual({
    text: "✨Hello world!",
  });

  // 导入 update1
  newDoc.import(update1);
  expect(newDoc.toJSON()).toStrictEqual({
    text: "😶‍🌫️✨Hello world!",
  });
}

{
  /**
   * 也可以批量导入
   */
  const newDoc = new LoroDoc();
  newDoc.importUpdateBatch([update1, update0, data]);
  expect(newDoc.toJSON()).toStrictEqual({
    text: "😶‍🌫️✨Hello world!",
  });
}
```

如果增量过多，可以重新导出一个快照，以提升导入速度并减小数据体积。

导出的二进制数据可以存储在任意位置，由你决定。

## 同步

两个存在并发编辑的文档，只需交换两次消息即可完成同步。

以下示例演示了两个文档之间的同步流程：

```ts twoslash
import { LoroDoc, LoroList, LoroMap, LoroText } from "loro-crdt";
import { expect } from "expect";
// ---cut---
const docA = new LoroDoc();
const docB = new LoroDoc();
const listA: LoroList = docA.getList("list");
listA.insert(0, "A");
listA.insert(1, "B");
listA.insert(2, "C");
// B 导入来自 A 的操作
const data: Uint8Array = docA.export({ mode: "update" });
// 通过网络将数据发送给 B
docB.import(data);
expect(docB.toJSON()).toStrictEqual({
  list: ["A", "B", "C"],
});

const listB: LoroList = docB.getList("list");
listB.delete(1, 1);

// `doc.export({ mode: "update", from: version })` 会将某版本以来的所有操作打包
// `version` 即另一文档的版本向量
const missingOps = docB.export({
  mode: "update",
  from: docA.oplogVersion(),
});
docA.import(missingOps);
expect(docA.toJSON()).toStrictEqual({
  list: ["A", "C"],
});
expect(docA.toJSON()).toStrictEqual(docB.toJSON());
```

## 事件

你可以订阅 `Container` 的事件。

`LoroText` 与 `LoroList` 的事件以 [Quill Delta](https://quilljs.com/docs/delta/) 格式呈现。

事件会在事务提交后触发。事务会在以下情况提交：

- 调用了 `doc.commit()`。
- 调用了 `doc.export(mode)`。
- 调用了 `doc.import(data)`。
- 调用了 `doc.checkout(version)`。

下面的示例展示了富文本事件：

```ts twoslash
import { LoroDoc, LoroList, LoroMap, LoroText } from "loro-crdt";
import { expect } from "expect";
// ---cut---
// 代码改编自 https://github.com/loro-dev/loro-examples-deno
const doc = new LoroDoc();
const text = doc.getText("text");
text.insert(0, "Hello world!");
doc.commit();
let ran = false;
text.subscribe((e) => {
  for (const event of e.events) {
    if (event.diff.type === "text") {
      expect(event.diff.diff).toStrictEqual([
        {
          retain: 5,
          attributes: { bold: true },
        },
      ]);
      ran = true;
    }
  }
});
text.mark({ start: 0, end: 5 }, "bold", true);
doc.commit();
await new Promise((r) => setTimeout(r, 1));
expect(ran).toBeTruthy();
```

事件类型定义如下：

```ts twoslash
import { Path, Diff, Frontiers, ContainerID } from "loro-crdt";

export interface LoroEventBatch {
  /**
   * 事件触发方式：
   *
   * - `local`：由本地事务触发。
   * - `import`：由导入操作触发。
   * - `checkout`：由 checkout 操作触发。
   */
  by: "local" | "import" | "checkout";
  origin?: string;
  /**
   * 当前事件接收者的容器 ID。
   * 如果订阅者是根文档，则为 undefined。
   */
  currentTarget?: ContainerID;
  events: LoroEvent[];
  from: Frontiers;
  to: Frontiers;
}

/**
 * Loro 的具体事件。
 */
export interface LoroEvent {
  /**
   * 事件目标的容器 ID。
   */
  target: ContainerID;
  diff: Diff;
  /**
   * 事件触发器的绝对路径，可以是列表容器的索引或 map 容器的键。
   */
  path: Path;
}
```
