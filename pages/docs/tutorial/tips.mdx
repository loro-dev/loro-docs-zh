# 使用小贴士

##### 每次创建 `LoroDoc` 都会分配新的随机 PeerID

<details>
<summary>如果我需要初始状态怎么办？</summary>

如果文档需要初始内容，切勿在调用 `new LoroDoc()` 后直接通过编辑来构造这个状态。否则每次有人打开文档，都会因为使用不同的 PeerID 而产生一批仅用于初始化的操作。

更好的方式是：预先生成一个快照，所有用户都从同一份快照加载，这样既能确保起点一致，也不会产生多余的操作。

</details>

---

##### 使用 `doc.setPeerId(newId)` 时务必谨慎

调用 `setPeerId` 时必须保证不会有两个并行节点使用相同的 PeerID，否则会引发严重的一致性问题。

如果计划在多个会话中复用某个 PeerID，请务必将该 PeerID 对应的本地文档数据一同持久化，并在导入任何远端更新之前先加载它。否则，同一对 `peerId + counter` 可能对应两次不同的操作，造成无法自动修复的分叉。

<details>
<summary>为什么会这样？</summary>

Loro 根据操作 ID 判断某个操作是否已经包含在文档中，而操作 ID 由 `PeerId + Counter` 组成。如果复用了 PeerID，就可能生成重复的操作 ID。在同步时，Loro 可能误以为某些操作已经处理，导致各副本状态不一致。

</details>

<details>
<summary>如何安全复用 PeerID？</summary>

复用 PeerID 的需求并不常见，若确实需要，请谨慎处理：不要把 PeerID 固定给某个用户（同一用户可能有多台设备），也不要固定给设备（同一浏览器可能开多个标签页）。

如确需复用，应结合锁等机制管理本地缓存：例如只允许一个标签页“占用”特定 PeerID，其余标签使用随机 ID；占用结束后再释放 PeerID。同时，避免让多个标签页或进程同时使用同一个 PeerID，以免产生重复的操作 ID。

</details>

---

##### 根容器无需操作即可初始化

在 Loro 中，根容器是隐式创建的。例如调用 `doc.getText("text")` 时不会在历史中生成任何操作，也无需与其他节点同步。

这与非根容器不同：执行 `doc.getMap("meta").setContainer("text", new LoroText())` 时，会产生“将 LoroText 插入 map”这一操作。

---

##### 并行初始化 LoroMap 的子容器时，可能发生覆盖而非自动合并

<details>
<summary>为什么会发生覆盖？</summary>

因为并行创建子容器会产生不同的 ContainerID，从而无法自动合并内容。当容器承载大量数据或是核心存储时，被覆盖会隐藏甚至丢失重要信息。

```ts twoslash
import { LoroDoc, LoroText } from "loro-crdt";
// ---cut---
const doc = new LoroDoc();
const map = doc.getMap("map");

// 并行初始化子容器
const docB = doc.fork();
const textA = doc.getMap("map").setContainer("text", new LoroText());
textA.insert(0, "A");
const textB = docB.getMap("map").setContainer("text", new LoroText());
textB.insert(0, "B");

doc.import(docB.export({ mode: "update" }));
// 结果：要么 { "meta": { "text": "A" } }，要么 { "meta": { "text": "B" } }
```

</details>

<details>
<summary>初始化容器的最佳实践</summary>

1. 在使用 Map 容器时：
   - 尽量在创建 Map 时一次性初始化所有子容器
   - 避免并发创建相同键的子容器，以防覆盖
2. 如果无法一次性初始化所有子容器，优先在根层级而非嵌套层级创建。
   - 例如使用 `doc.getMap("user." + userId)`，而不是 `doc.getMap("user").getOrCreateContainer(userId, new LoroMap())`

</details>

##### 使用脱敏（redaction）安全分享文档历史

有时用户会误粘贴敏感信息（API Key、密码、隐私数据）。需要“只删除敏感内容而保留历史一致性”的办法。

<details>
<summary>如何安全地做内容脱敏？</summary>

Loro 提供 `redactJsonUpdates` 方法，可针对指定版本区间选择性脱敏操作。

例如用户误贴了密码或密钥：

```ts no_run twoslash
import { LoroDoc, redactJsonUpdates } from "loro-crdt";
// ---cut---
const doc = new LoroDoc();
doc.setPeerId("1");

// 创建需要脱敏的内容
const text = doc.getText("text");
text.insert(0, "Sensitive information");
doc.commit();

const map = doc.getMap("map");
map.set("password", "secret123");
map.set("public", "public information");
doc.commit();

// 导出 JSON 更新
const jsonUpdates = doc.exportJsonUpdates();

// 定义需要脱敏的版本区间（文本内容）
const versionRange = {
  "1": [0, 21], // 脱敏 "Sensitive information"
};

// 执行脱敏
const redactedJson = redactJsonUpdates(jsonUpdates, versionRange);

// 使用脱敏数据创建新文档
const redactedDoc = new LoroDoc();
redactedDoc.importJsonUpdates(redactedJson);

// 文本内容已被替换为占位字符
console.log(redactedDoc.getText("text").toString());
// 输出: "���������������������"

// 还可以针对特定 map 条目脱敏
const versionRange2 = {
  "1": [21, 22], // 脱敏 "secret123" 密码
};

const redactedJson2 = redactJsonUpdates(jsonUpdates, versionRange2);
const redactedDoc2 = new LoroDoc();
redactedDoc2.importJsonUpdates(redactedJson2);

console.log(redactedDoc2.getMap("map").get("password")); // null
console.log(redactedDoc2.getMap("map").get("public")); // "public information"
```

这样做的好处：

1. 保留文档结构与 CRDT 一致性
2. 维持操作 ID、因果依赖等元数据
3. 脱敏后仍可继续协同编辑
4. 只替换指定操作，不影响整个文档

脱敏遵循以下规则：

- 保留删除、树节点移动、列表移动等操作
- 文本插入被替换为 Unicode 替换字符 `�`
- 列表与 Map 插入的值替换为 `null`
- 保持子容器结构
- 文本标注值替换为 `null`
- Map 键与文本标注键保持不变

**重要提示**：必须确保所有节点都接收到脱敏后的版本，否则其他节点仍持有包含敏感信息的原始文档。

</details>

##### 使用浅快照彻底移除旧历史

当需要删除某个时间点之前的全部历史时，浅快照是理想方案。

<details>
<summary>如何用浅快照删除旧历史？</summary>

浅快照会生成一个仅保留当前状态的新文档，类似 Git 的浅克隆，指定时间点之前的历史都会被完全移除。

```ts twoslash
import { LoroDoc } from "loro-crdt";
// ---cut---
const doc = new LoroDoc();
doc.setPeerId("1");

// 旧历史 —— 将被移除
const text = doc.getText("text");
text.insert(0, "This document has a long history with many edits");
doc.commit();
text.insert(0, "Including some potentially sensitive information. ");
doc.commit();

// 新的历史 —— 将被保留
text.delete(11, 55); // 删除中间部分
text.insert(11, "with sanitized history");
doc.commit();

// 创建仅保留当前状态的浅快照
const sanitizedSnapshot = doc.export({
  mode: "shallow-snapshot",
  frontiers: doc.oplogFrontiers(),
});

// 用浅快照生成新文档
const sanitizedDoc = new LoroDoc();
sanitizedDoc.import(sanitizedSnapshot);

// 文档保持最终状态
console.log(sanitizedDoc.getText("text").toString());
// 输出: "Including with sanitized history"

// 但浅快照之前的历史全部删除
console.log(sanitizedDoc.isShallow()); // true
console.log(sanitizedDoc.shallowSinceFrontiers()); // 显示起始版本
```

适用场景：

1. 将可能包含敏感信息的旧历史彻底清除
2. 显著减小文档体积
3. 在里程碑节点之后创建干净版本
4. 保证旧操作无法恢复

与脱敏对比：

- 浅快照会删除指定版本点之前的所有操作
- 脱敏只替换特定操作的内容

**重要提示**：两种方式都能维持后续同步一致性，但必须将清理后的文档分发给所有节点，否则其他节点仍保留原始数据。

**何时使用哪种方式？**

- 当需要保留历史但去除局部敏感内容时，使用 **脱敏**
- 当希望删除某个时间点之前的全部历史时，使用 **浅快照**

</details>

##### 可以在文档中维护 PeerID 与用户 ID 的映射

通过 `doc.subscribeFirstCommitFromPeer(listener)`，在某个 Peer 第一次提交时记录其用户信息。

<details>
<summary>如何追踪 Peer 与用户的对应关系？</summary>

在协作应用中，你通常需要在用户 ID 与 PeerID 之间进行双向映射：

- **查找用户的所有编辑**：需要先找出该用户对应的所有 PeerID
- **展示编辑归属**：操作记录中只存 PeerID，需要在界面上映射回用户 ID

这个 hook 会在每个 Peer 第一次提交时触发，适合在文档中写入作者信息等元数据。

```ts twoslash
import { LoroDoc } from "loro-crdt";
import { expect } from "expect";
// ---cut---
const doc = new LoroDoc();
doc.setPeerId(0);
doc.subscribeFirstCommitFromPeer((e) => {
  doc.getMap("users").set(e.peer, "user-" + e.peer);
});
doc.getList("list").insert(0, 100);
doc.commit();
await Promise.resolve();
expect(doc.getMap("users").get("0")).toBe("user-0");
```

这样可以：

1. 自动追踪参与协作的 Peer
2. 在文档中保存用户元数据（姓名、邮箱等）
3. 构建作者标注、在线状态、编辑记录等功能

映射信息保存在文档内部，会随文档状态自动同步与持久化。

</details>
