## 新增

### 1. 新的钩子

`doc.subscribePreCommit(listener)` - 在处理前修改提交选项：

这个钩子特别有用，因为 `doc.commit()` 通常在各种方法中被隐式调用，例如 `doc.import`、`doc.export`、`doc.checkout` 和 `doc.exportJsonUpdates`。没有这个钩子，试图为每个提交添加自定义消息的用户可能会错过这些隐式提交触发器。

```ts
const doc = new LoroDoc();
doc.setPeerId(0);
doc.subscribePreCommit((e) => {
  e.modifier.setMessage("test").setTimestamp(Date.now());
});
doc.getList("list").insert(0, 100);
doc.commit();
expect(doc.getChangeAt({ peer: "0", counter: 0 }).message).toBe("test");
```

高级示例 - 创建一个 Merkle DAG：

```ts no_run
const doc = new LoroDoc();
doc.setPeerId(0);
doc.subscribePreCommit((e) => {
  const changes = doc.exportJsonInIdSpan(e.changeMeta);
  expect(changes).toHaveLength(1);
  const hash = crypto.createHash("sha256");
  const change = {
    ...changes[0],
    deps: changes[0].deps.map((d) => {
      const depChange = doc.getChangeAt(idStrToId(d));
      return depChange.message;
    }),
  };
  hash.update(JSON.stringify(change));
  const sha256Hash = hash.digest("hex");
  e.modifier.setMessage(sha256Hash);
});

doc.getList("list").insert(0, 100);
doc.commit();

expect(doc.getChangeAt({ peer: "0", counter: 0 }).message).toBe(
  "2af99cf93869173984bcf6b1ce5412610b0413d027a5511a8f720a02a4432853",
);
```

`doc.subscribeFirstCommitFromPeer(listener)` - 在第一次对等交互时触发：

这个钩子为将对等信息（例如作者身份）与文档关联提供了一个理想的点。

```ts
const doc = new LoroDoc();
doc.setPeerId(0);
doc.subscribeFirstCommitFromPeer((e) => {
  doc.getMap("users").set(e.peer, "user-" + e.peer);
});
doc.getList("list").insert(0, 100);
doc.commit();
expect(doc.getMap("users").get("0")).toBe("user-0");
```

### 2. EphemeralStore

EphemeralStore 是 Awareness 用于临时状态的更好替代方案：

Awareness 通常用作基于状态的 CRDT，用于处理实时协作场景中的临时状态，例如光标位置和应用程序组件高亮。随着应用程序复杂性的增长，Awareness 可能会在多个地方设置，从光标位置到用户在线状态。然而，当前版本的 Awareness 不支持部分状态更新，这意味着即使是轻微的鼠标移动也需要同步整个 Awareness 状态。

```ts no_run
awareness.setLocalState({
  ...awareness.getLocalState(),
  x: 167,
});
```
由于 Awareness 主要用于一致性要求相对较低的实时协作场景，我们可以使其更加灵活。我们引入了 EphemeralStore 作为 Awareness 的替代方案。可以把它想象成一个简单的键值存储，它使用基于时间戳的最后写入获胜来解决冲突。您可以根据应用程序的需求为键值对选择适当的粒度，并且只同步修改后的键值对。


```ts
import {
    EphemeralStore,
    EphemeralListener,
    EphemeralStoreEvent,
} from "loro-crdt";

const store = new EphemeralStore();
// 设置临时数据
store.set("user-alice", {
    anchor: 10,
    focus: 20,
    user: "Alice"
});

// 仅编码 `loro-prosemirror` 的数据
const encoded = store.encode("user-alice")
const newStore = new EphemeralStore();
newStore.subscribe((e: EphemeralStoreEvent) => {
    // 监听来自 `local`、`remote` 或 `timeout` 事件的更改
});

newStore.apply(encoded);
console.log(newStore.get("user-alice"))
// {
//     anchor: 10,
//     focus: 20,
//     user: "Alice"
// }
```

## 修复

- 修复了在末尾“\n”字符处的文本样式问题
- 为当前事务操作添加了 JSON 支持
- 对于支持多线程的环境，例如 Rust 和 Swift，LoroDoc 现在可以直接且安全地在多个线程之间并行共享和访问，而不会触发之前的 WouldBlock panic。
